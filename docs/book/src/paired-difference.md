## One-step scenario comparison

**Tempting claim:** using the same noise always makes a difference estimate less
variable. **Hypotheses:** X and Y are rational affine functions of finitely many
independent uniform owners on compact rational intervals. A repeated owner
inside this joint law denotes the same draw with the same interval. Inputs
already determine dependence; the report does not construct a coupling.

Call `pairedDifferenceReport` in `Markovian.Continuous.Measure.Exact` on that
joint law. The three experiments below use `materializeJointAffineKernel`:

- X=U, Y=U for U uniform on [0,1]: covariance 1/12 and difference variance **0**.
- X=U, Y=1-U: covariance **-1/12** and difference variance **1/3**.
- X=U, Y=V with independent uniform owners: covariance 0 and difference
  variance **1/6**.

All three have means 1/2, marginal variances 1/12, mean difference 0, and an
independent-marginal variance baseline of 1/6. Thus common noise **doubles**
the difference variance in the second experiment, despite identical marginals.
The signed excess is respectively -1/6, +1/6, and 0; the comparison is LT, GT,
and EQ. It is not an unsigned "variance reduction" score.

\\[
\operatorname{Var}(X-Y)=\operatorname{Var}(X)+\operatorname{Var}(Y)-2\operatorname{Cov}(X,Y).
\\]

**Exercise:** why does 1-U reverse the benefit of sharing? **Hint:** center both
coordinates at their means. **Checked answer:** the centered values have
opposite signs, so their product has expectation -1/12. The centered difference
is 2(U-1/2), with variance 4/12=1/3. The fixture checks all nine report fields
against a direct affine uniform formula. In particular its independent oracle
computes difference variance directly from squared difference coefficients,
not by calling production expansion or reusing the reported covariance.

This is one-step comparison only. There is no trajectory synchronization,
policy comparison, arbitrary coupling solver, sampling estimate, optimization
or universal variance-reduction result. Existing reward/successor joints keep
their correlation and timing; this operation does not execute an MDP or change
terminal/horizon semantics. Exact Rational arithmetic stays separate from
floating backends. EL-03 remains Proposed; this is unreleased fixture evidence,
not its acceptance or publication. D-079's separate bounded, unreleased acceptance
for joint affine kernels and left-successor substitution does not accept EL-03.

## What a budget admits

The report uses one operation-wide meter, not five independently budgeted public
moment calls. After validating limits and bounding the two retained law spines,
it requires degree 2 and five input terms even for Dirac laws. It reserves
`n+m+(n+m)^2+5` structural units, with saturated preflight arithmetic, before
checking ownership and shared intervals. It observes constants and retained
coefficient/endpoint triples, then accounts support arithmetic left before right.
It evaluates X, Y, X², Y² and XY in that order using the existing expansion
machinery without resetting any count. Eleven derived Rational operations and
one comparison add twelve work units. Accessors only project retained fields.

Raw Cartesian pairs accumulate across all five moments; the canonical-term
limit bounds the largest live expansion, not the sum of finalized moments.
Every rational intermediate counts, even if later cancelled or discarded.
Work is checked before each arithmetic operation. Failure returns only an
`ExactError`, never a partial report or ledger. Rejected counts saturate at
limit plus one. Construction is separately budgeted; these semantic charges
are not timing estimates. The older bivariate API and its accounting/failure
precedence remain unchanged. The [frozen contract](../../plans/EL-03-PAIRED-DIFFERENCE.md)
gives the complete operation order.

**Exercise:** can a constant pair with zero difference variance exceed a
rational-bit limit? **Hint:** the algorithm still evaluates both squares.
**Checked answer:** yes. For X=Y=8, input 8 fits four bits but the intermediate
64 requires seven; four bits rejects it despite the final zero variance. The
normal suite also checks discarded support-product growth and work-before-bit
failure when both limits fail at the same derived step.
